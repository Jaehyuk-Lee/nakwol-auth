# 시즌3 멤버와 서버 접근 제어

설치·배포·검증 방법은 [Connect 서버 보호 안내](CONNECT_SERVER_PROTECTION.md)를 따릅니다.

## 현재 권한 계약

- Discord 서버 `1493410906456064112`, 멤버 기준은 시즌3 역할 `1553600098661957643`입니다.
- `member`는 시즌3 필수, `guest`는 활성 Discord 로그인 사용자, `admin`은 활성 AUTH 운영자입니다.
- 앱별 추가 역할은 시즌3와 함께 모두 충족해야 하며, guest/admin 변경으로 우회되지 않습니다.
- 일반 개발자는 자신이 소유한 앱의 member/guest 정책을 선택합니다. 추가 역할 설정은 AUTH 운영자만 관리합니다.

## 역할 조회와 접근 검사

로그인용 Discord OAuth가 본인의 역할 목록을 읽고 저장합니다. `/authorize`, `/token`, `/me`는 이 저장된 정보로 접근 정책을 판정합니다. **봇은 로그인에 필수가 아닙니다.** 기존 SSO가 허용되는 경우 OAuth를 다시 거치지 않으므로, 역할 제거가 즉시 반영되지는 않습니다. 역할 기반 접근은 마지막 Discord 확인 후 24시간이 지나면 재로그인을 요구합니다. 거절된 세션에서 수동 로그인을 선택하면 Discord 역할을 다시 읽습니다.

Connect 0.7.0 서버 게이트는 최초 세션 교환과 5분 authorization lease 만료 시 `/me`로 앱 토큰·사용자·정책을 확인합니다. lease가 유효한 동안 HTML·JS·CSS·JSON·이미지·폰트·다운로드는 앱/사이트/AUTH origin/정책에 바인딩된 AES-GCM 쿠키를 로컬에서 검증한 뒤 제공합니다. 이미지마다 중앙 AUTH나 D1/KV/R2를 조회하지 않습니다.

`/me` 성공의 `expires_at`은 Unix 밀리초입니다. 서버 세션은 생성 후 1시간과 앱 토큰 만료 중 빠른 시점에 만료되며, lease도 그 만료를 넘지 않습니다. 같은 isolate의 동시 재검증은 병합하고 완료 결과를 고정 lease 만료까지만 재사용합니다. 여러 isolate가 동시에 갱신하면 각각 호출할 수 있습니다.

AUTH 장애 시 유효 lease는 만료까지 유지됩니다. 만료 후 재검증 실패는 503으로 차단하며 오래된 승인을 연장하지 않습니다. **운영자 차단·토큰 폐기 등 중앙 권한 회수에는 최대 5분의 추가 지연이 생깁니다.** Discord 역할 정보 자체의 최대 24시간 지연과 별개이므로 역할 제거 반영은 최대 24시간 + 5분이 될 수 있습니다. 로그아웃은 사이트 쿠키를 지우고 현재 isolate에서 토큰을 거부하며 중앙 폐기를 시도합니다. 다른 isolate의 재생 쿠키는 기존 lease 만료까지 유효할 수 있습니다.

기존 0.6.x 설치는 자동 전환되지 않습니다. 0.7.0을 명시적으로 선택해 `protect update`한 뒤 사이트를 빌드·배포해야 합니다. 이 문서는 소스 계약이며 운영 반영을 뜻하지 않습니다.

## 운영자 역할 관리

`/admin/roles`에서 앱별 추가 역할 조건을 관리합니다. 빈 배열은 시즌3만 요구합니다. 실제 Discord 역할 목록을 불러오는 운영자 기능은 별도로 봇이 필요하며, 봇 없는 환경에서 사용할 수 있다고 안내하면 안 됩니다. Discord 역할 생성·부여·회수는 Discord에서 수행합니다.

## 검증 범위

`protect verify`는 배포 주소의 비로그인 직접 접근 차단을 검사합니다. 실제 계정의 OAuth, Discord 역할 변경 감지, 전체 외부 배포 주소의 안전성을 대신 증명하지 않습니다. 상세 확인 순서는 연결된 안내를 참고하세요.
