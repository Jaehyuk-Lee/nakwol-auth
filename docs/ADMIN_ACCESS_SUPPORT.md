# 관리자 접근 문제 해결

앱 관리(`/admin/apps`)에서 서비스를 선택한 뒤 **접근 문제 해결 · 수동 권한**을 사용합니다.

1. Discord 사용자 ID(닉네임이 아닌 숫자 ID)를 입력하고 **계정 진단**을 누릅니다.
2. 저장된 역할의 확인 시각, 부족한 역할 ID, 현재 판정, 인증 기록을 확인합니다.
3. 사유를 입력하고 수동 허가, 허가 회수, 재인증 요구 중 하나를 실행합니다.

## 수동 허가

선택한 member/guest 서비스에서만 시즌3·추가 역할 조건을 대신하는 예외입니다. 가입 전 ID에도 등록할 수 있으며 실제 Discord 로그인으로 동일 ID를 확인해야 적용됩니다. Discord 역할, 전역 맹원 자격, AUTH 운영자 및 lab 권한은 바뀌지 않습니다. 비활성 계정/서비스, 재인증 요구를 우회하지 않습니다.

회수는 예외만 제거합니다. 원래 역할 조건을 충족하는 사용자는 다시 접속할 수 있습니다. 해당 서비스의 기존 토큰과 인증 코드는 함께 회수합니다. 모든 조치는 대상, 운영자, 시각, 사유가 DB 트랜잭션 안에서 기록됩니다.

## 재인증 요구

사용자의 모든 중앙 세션, AUTH 토큰, 인증 코드를 무효화합니다. 새 Discord 로그인으로 역할을 읽기 전까지 새 토큰 발급도 거부합니다. 다른 서비스에도 영향을 주므로 화면의 확인 내용을 읽고 실행하세요. 운영자 자신은 이 기능 대신 로그아웃 후 로그인합니다.

봇은 필요하지 않습니다. 관리자가 현재 Discord 역할을 즉시 조회하는 기능이 아니며, 역할 정보는 사용자가 Discord로 로그인할 때 갱신됩니다.

## 권한이 없어 로그인에 실패했을 때

서비스 접근까지 허용된 경우에만 중앙 세션 쿠키를 발급합니다. 거부된 기존 중앙 세션은 제거합니다. SDK 0.3.1은 접근 거부 시 해당 서비스의 앱 토큰·사용자 캐시를 지우고 자동 재시도를 멈춥니다. Connect의 **Discord로 권한 다시 확인** 버튼으로 새 로그인을 시작할 수 있습니다. 권한 판정에 사용하는 역할 확인 기록과 관리자용 실패 로그는 남습니다. 이것은 로그인 자격 증명을 저장하는 것과 별개입니다.

## 서비스 연동 조건

서버는 보호된 요청마다 AUTH `/me`를 확인해야 합니다. 자체 세션만 신뢰하거나 결과를 캐시하는 외부 서비스는 중앙 회수가 즉시 반영되지 않습니다. 이미 전달된 콘텐츠는 회수할 수 없습니다.

`/me`의 `data.membership`은 실제 Discord 멤버 상태를 그대로 유지합니다. 수동 허가는 별도 `application_access: {client_id, allowed, source: 'manual_grant'}`로 전달됩니다. 최신 공식 Connect 서버 게이트는 이를 처리합니다. 기존 자체 게이트가 `membership.is_member`만 검사한다면 해당 사이트 개발자가 이 서비스별 판정도 반영해야 합니다.

## 기록 범위

서비스별 인증·관리자 조치 기록을 50건씩 조회하고 Discord ID로 필터링합니다. 사용자 ID 확인 전 실패는 사용자 미확인으로 표시됩니다. 서비스 자체의 내부 오류 및 모든 정적 파일 요청을 수집하지는 않습니다. 옛 기록에는 상세 판정이 없을 수 있습니다. 현재 진단과 당시 이벤트를 구분하세요.

## 릴리스

`0013_access_support.sql` 마이그레이션을 AUTH DB에 먼저 적용한 뒤 Worker를 배포합니다. 새 테이블이 없는 배포는 인증을 처리할 수 없습니다. Connect 서버 게이트 변경은 CLI 배포 및 각 서비스의 재생성·재배포가 필요합니다. 운영 반영은 저장소의 dev → main → stable 절차를 따릅니다.
